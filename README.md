# japan-trip-2026

טיול ליפן, 21.10 עד 5.11.2026.

**האפליקציה:** https://japan-trip-2026-azure.vercel.app

אותו מבנה ועיצוב כמו האפליקציה של ספרד (`barcelona-madrid-2026`): חמש לשוניות (מסלול, הזמנות, אוכל, קניות, ציוד ומידע), לוח ימים בצבעי האזורים, והיום מצויר כקו רכבת שבו כל פעילות היא תחנה.

- [`src/`](src/): קוד המקור. `node build.mjs` בונה ממנו את `index.html`
- [`itinerary.md`](itinerary.md): המסלול המלא, יום אחרי יום, ברשימות רגילות
- [`source/JAPAN_2026.pdf`](source/JAPAN_2026.pdf): הגיליון המקורי

התכנון מהגיליון לא שונה. התוספות מסומנות כ״הצעה״, בתחנה מקווקוות.

## האפליקציה

- עובדת גם בלי אינטרנט, אחרי פתיחה ראשונה (`sw.js`)
- אפשר להוסיף למסך הבית (`manifest.webmanifest`)
- לפני הטיול מופיעה ספירה לאחור. בזמן הטיול היא פותחת את היום הנוכחי לפי שעון יפן, ומסמנת את התחנה הבאה
- אפשר לסמן תחנות, לערוך, להוסיף ולכתוב הערות לכל יום
- סנכרון בין הטלפונים: דרך `api/state.js` ו-Upstash Redis. בלי מסד נתונים מחובר, כל טלפון שומר את השינויים אצלו

## פריסה ב-Vercel

אין שלב build ב-Vercel: `index.html` שבריפו הוא מה שעולה, אז בונים אותו לפני כל commit. הקבצים `src/`, `tools/`, `source/`, `itinerary.md` ו-`README.md` לא עולים לאתר (ראו `.vercelignore`), והאתר מסומן כך שמנועי חיפוש לא יאנדקסו אותו.

כדי שהשינויים יסונכרנו בין שני טלפונים: ב-Vercel, בפרויקט, **Storage ← Upstash for Redis**, ולחבר את המסד לפרויקט. המשתנים `KV_REST_API_URL` ו-`KV_REST_API_TOKEN` נוספים לבד.

## התקנה בטלפון

- **iPhone (Safari):** שיתוף ← הוסף למסך הבית
- **Android (Chrome):** תפריט ⋮ ← התקנת אפליקציה
